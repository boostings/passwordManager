# CERT exceptions ledger

Every scanner suppression (SpotBugs exclude, `@SuppressWarnings("PMD.…")`, Semgrep `nosemgrep`)
must have a row here. Each one is as narrow as the tool allows (one class, one method, one rule)
and needs security-owner sign-off before the milestone closes.

**M1 review (2026-10-03, security owner):** every suppression in the tree was listed
(`tools/cert-rules/spotbugs-exclude.xml`, `@SuppressWarnings` in `modules/*/src`, `NOPMD`, `nosemgrep`,
`gitleaks:allow`) and matched to a row; each row was re-checked against the current code. One
unledgered suppression was found and added as CE-006. No `NOPMD`, `nosemgrep` or `gitleaks:allow` exist.

| CE-001 | FindSecBugs `CIPHER_INTEGRITY` (CWE-353) | `pm.crypto.KeyWrap#initCipher` (`tools/cert-rules/spotbugs-exclude.xml`) | False positive. The transformation is `AES/KWP/NoPadding` (RFC 5649 AES Key Wrap with Padding, ADR 0004). KWP is a deterministic authenticated-encryption mode: unwrap verifies the alternative initial value and the padding length, and any wrong KEK or modified byte fails with a `GeneralSecurityException`, mapped to `AUTH_FAILED`. The detector only treats GCM as integrity-protecting. Covered by `KeyWrapTest` (RFC 5649 vectors, wrong-KEK and bit-flip properties). The SpotBugs match is name-based on `initCipher`: renaming that method silently stops the exclusion from matching (the finding then returns and fails the gate). | Signed off 2026-10-03 (security owner, @boostings) |
| CE-002 | PMD `DoNotUseThreads` (TPS00-J) | Class-level `@SuppressWarnings("PMD.DoNotUseThreads")` on `pm.tui.IdleLock` (main) and on the test classes `pm.tui.IdleLockTest` and `pm.tui.IdleLockFakeScheduler` | TPS00-J requires executors instead of ad-hoc threads; PMD 7's rule also reports `ExecutorService`/`Executors`, which is what fires on all three classes. `IdleLock` runs its timer on a single-thread `ScheduledExecutorService`; the one `new Thread(r, "pm-idle-lock")` is inside that executor's `ThreadFactory` (to name it and mark it daemon), not an ad-hoc thread. It also uses `Thread.currentThread()` and an `UncaughtExceptionHandler`. The two test classes cannot drop the suppression: without it PMD flags `IdleLockFakeScheduler` (an `AbstractExecutorService` double) and every use of it in `IdleLockTest`. (Corrected 2026-10-02 after the Lane E review: the earlier text said no raw `Thread` was created and that only one class was suppressed; both were wrong.) | Signed off 2026-10-03 (security owner, @boostings) |
| CE-003 | SpotBugs `EI_EXPOSE_REP`, `EI_EXPOSE_REP2` (OBJ05-J, OBJ06-J) | `pm.vault.CreatedVault`, `pm.tui.CreatedSession` (`tools/cert-rules/spotbugs-exclude.xml`) | Intentional. These records hand the caller a live handle to the unlocked vault/session plus the one-time recovery key; ownership transfers to the caller, who closes both. A defensive copy of an unlocked vault is meaningless. SpotBugs treats `Vault`/`Session` as mutable because of `put`/`remove`. Restricted to these two classes and two patterns. The `CreatedVault` row was added by Lane E against the §2 stub; Lane C inherits it when replacing the file. | Signed off 2026-10-03 (security owner, @boostings) |
| CE-004 | PMD `CompareObjectsWithEquals` (EXP03-J); SpotBugs `EC_UNRELATED_TYPES_USING_POINTER_EQUALITY` | `pm.crypto.SecretBytes#refuseEscape` (method-level `@SuppressWarnings("PMD.CompareObjectsWithEquals")`; `tools/cert-rules/spotbugs-exclude.xml`) | Intentional. `apply`/`applyCrypto` must refuse a function that returns the internal buffer itself, so the check is `result == buf`, marked `// CE-004: deliberate identity check`. Reference identity is the property being tested: `equals` on arrays is already identity but hides that, and content equality would wrongly refuse a legitimate copy. The earlier `IdentityHashMap` lookup did the same thing only to keep the linters quiet and was replaced. Error Prone `ReferenceEquality` does not fire (no `equals` override is involved). The SpotBugs match is name-based on `refuseEscape`; renaming breaks it. Covered by `SecretBytesTest` (returning the buffer throws `SECRET_ESCAPE`, a copy passes). | Signed off 2026-10-03 (security owner, @boostings) |
| CE-005 | SpotBugs `DM_GC` (performance) | `pm.crypto.Kdf#collectGarbage` (`tools/cert-rules/spotbugs-exclude.xml`) | Intentional. Before running Argon2, `Kdf.argon2id` refuses with `BAD_PARAMS` when `memoryKiB * 1024 * 11/10` exceeds the free heap (max minus `totalMemory() - freeMemory()`), so a hostile header cannot exhaust the heap. "In use" counts unreachable garbage, such as the Argon2 blocks `Kdf.tune` just timed, so on a small heap (123 MiB) the first figure wrongly refuses the floor. `System.gc()` runs only when the first figure falls short, once, and the check is then repeated. The match is name-based on `collectGarbage`; renaming the method breaks it. | Signed off 2026-10-03 (security owner, @boostings) |
| CE-006 | Error Prone `ArrayRecordComponent` (EXP02-J, OBJ05-J) | `pm.vault.cbor.CborValue.Bytes` (record-level `@SuppressWarnings("ArrayRecordComponent")`) | Intentional. The §2 D frozen contract makes `CborValue.Bytes` a record over `byte[]`. The check warns that a record's generated `equals`/`hashCode`/`toString` and accessor use the array by identity and expose it. All four are replaced: the compact constructor and `value()` clone, `equals` compares content through `pm.crypto.ConstantTime.equals` (SR-016), and `hashCode`/`toString` use only the length, so the bytes (possibly a secret) never reach a log. `wipe()` zeroes the internal copy. Covered by `CborWriterReaderTest.bytesComparesByContentAndHidesItFromToStringAndHashCode`. (Added 2026-10-03: the M1 security-owner review found this suppression had no ledger row.) | Signed off 2026-10-03 (security owner, @boostings) |
| CE-007 | FindSecBugs `COMMAND_INJECTION` (CWE-78, IDS07-J) | `pm.approval.run.EnvRunner#start` (`tools/cert-rules/spotbugs-exclude.xml`) | Intentional. `pm env run` exists to run the user's command with approved variables (approval-model §6). The argv is the user's own command line, is shown in full in the approval prompt, and goes to `ProcessBuilder` as a list, never through a shell, so no element is re-parsed (IDS07-J's concern). It is taken only from `ApprovalRequest.Display#argv()`, so what was approved is what runs (SR-102). Covered by `EnvRunnerTest.argvShownIsArgvExecutedWithoutShellExpansion` (`$(...)`, backticks, `;` and `*` arrive literally). The match is name-based on `start`. | Open: needs security-owner sign-off at M2.7 |
