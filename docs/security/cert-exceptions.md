# CERT exceptions ledger

Every scanner suppression (SpotBugs exclude, `@SuppressWarnings("PMD.…")`, Semgrep `nosemgrep`)
must have a row here. Each one is as narrow as the tool allows (one class, one method, one rule)
and needs security-owner sign-off before the milestone closes.

**M1 review (2026-10-03, security owner):** every suppression in the tree was listed
(`tools/cert-rules/spotbugs-exclude.xml`, `@SuppressWarnings` in `modules/*/src`, `NOPMD`, `nosemgrep`,
`gitleaks:allow`) and matched to a row; each row was re-checked against the current code. One
unledgered suppression was found and added as CE-006. No `NOPMD`, `nosemgrep` or `gitleaks:allow` exist.

**M2 review (2026-10-03, security owner, M2.7):** the same sweep, re-run with
`grep -rn 'SuppressWarnings\|NOPMD\|nosemgrep\|gitleaks:allow' modules/*/src tools` plus the
SpotBugs exclude file, found nine suppressions added during M2 with no row: four `DoNotUseThreads`
(added to CE-002), four `CloseResource` (CE-008) and one `ArrayRecordComponent` (CE-009), plus the
javac `module` lint suppression on `pm.vault` (CE-010). CE-007 was signed off. Every suppression in
the tree now maps to exactly one row.

**M7 review (2026-10-08, security owner, M7.5):** the same sweep,
`grep -rn 'SuppressWarnings\|NOPMD\|nosemgrep\|gitleaks:allow' modules/*/src tools extension`, plus the
SpotBugs exclude file, found 90 suppressions. 75 name their CE row inline; the 38 that name a row awaiting
sign-off (CE-035, CE-036, CE-037, CE-087, CE-088) were checked method by method against that
row's scope; the other 37 name rows signed off at earlier sweeps and were not re-read. Of the 15 without an inline number, 10 were already in a row (CE-004,
CE-006, CE-008, CE-009, CE-010, CE-021, CE-045; each location checked), four test
suppressions in three places from M7.10 had none and are now CE-089, and one was a dead
`checkstyle:ParameterNumber` (Checkstyle does not run), removed together with a second one inside
a CE-035 annotation. CE-035's scope gained `SocketApprovalHostTest#firstLogin` (M7.12). CE-035,
CE-036, CE-037, CE-087 and CE-088 were re-read against main and signed off. No `NOPMD`,
`nosemgrep` or `gitleaks:allow` exist.

**M4 review (2026-10-04, security owner, M4.5):** the same sweep was run again over the M4 code:
`grep -rn 'SuppressWarnings\|NOPMD\|nosemgrep\|gitleaks:allow' modules/*/src tools`, plus the
SpotBugs exclude file. It found twelve M4 suppressions, and each maps to a row (count corrected
at the M4.5 review, which had said eleven):
- `TestAgent`: CE-020.
- `pm.crypto` `module`: CE-021.
- `Hash#sha1ForBreachRange`, the SpotBugs lambda match: CE-015.
- `BreachClient#fetch` and `BreachClientTest`: CE-016.
- `TestSshAgent`, `HealthCommandTest`, `HealthCommand`, `SshCommands`, `SshCommandsTest` and
  `ToolsTest`: CE-045.
- `CliSshActions`: CE-046.

Each row's claim was checked against the code. CE-015 is the only SHA-1 use. `BreachClient#fetch`
and `HealthCommandTest` only re-assert the interrupt flag. `CliSshActions` uses one named daemon
single-thread executor. Each agent request, from its first byte written to its last reply byte
read, is bounded by `DEFAULT_TIMEOUT`; the connect before it is not (a blocking Unix-domain
connect), so a wedged connect can hold that thread, and the key buffer handed to it, until the
call returns (ADR 0013, Consequences). CE-015, CE-016, CE-045 and CE-046 were signed off. The M4.5 fuzz harnesses (`modules/pm-fuzz`) add no suppression.
